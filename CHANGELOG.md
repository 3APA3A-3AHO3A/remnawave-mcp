# Changelog

## 1.3.2 — 2026-10-06
По итогам аудита.

**Безопасность**
- Аргументы доп. команд (`find_user`, `user_report`, `geocheck_node`, `node_connections`, `user_connections`) проверяются по схеме и безопасно подставляются в адрес запроса. Раньше значение вида `../../…` могло увести запрос на любой адрес панели, в том числе на команды записи, даже в режиме «только чтение». HTTP-клиент дополнительно отказывается от адресов с сегментами `.` / `..`.
- Неизвестные аргументы больше не передаются в панель — команда возвращает понятную ошибку.

**Приватность**
- Ссылка подписки и `shortUuid` скрываются везде, в том числе в ответах команд подписок (`get_subscriptions`, `get_subscription_by_*`), где раньше проходили открыто.
- Логин и пароль в адресах вида `socks5://user:pass@host` (прокси нод) скрываются.
- IP клиента в отчётах торрент-блокера (`source`) и IP с портом заменяются псевдонимом — тем же, что и у IP без порта. IPv6 в текстах ошибок тоже.
- Скрываются любые поля `…Token` (`botToken`, `apiToken` и т.п.) в настройках интеграций, плагинов и метаданных.
- При совпадении коротких псевдонимов у разных значений второе получает более длинный псевдоним: одинаковый псевдоним всегда означает одно и то же значение.

**Исправления**
- Длинные списки верхнего уровня (`get_hosts`, `get_nodes`) сокращаются целиком с пометкой «показано N из M»; маленькие вложенные списки больше не урезаются.
- Неудачный или не дождавшийся ответа GeoCheck / список подключений не запоминается — повторный вызов проверяет заново.
- `REMNAWAVE_TIMEOUT_MS=0` — без таймаута, `REMNAWAVE_MAX_RESPONSE_CHARS=0` — без ограничения (раньше ломали все запросы).
- Подсказка о несовпадении версии панели учитывает способ установки: Docker — тег образа, расширение — файл `.mcpb`, исходники — команда `npm`.
- Ежедневная проверка релизов панели открывает PR только на более новую версию и не пересоздаёт его, если PR закрыли вручную.
- CI запускает Docker-образ, собранный под старую версию панели (3.3); текст релиза строится из списка версий проекта, а не вписан вручную.

**Документация:** описаны `REMNAWAVE_SHOW_SECRETS`, значение 0 у таймаута и длины ответа, исключение для `sharing_suspects`; обновлены таблица приватности и структура `src/`. `.mcp.json` добавлен в `.gitignore`.

57 автотестов.

## 1.2.1 — 2026-09-30
- **Claude Code:** инструкция по установке (`claude mcp add`), в т.ч. разные панели в разных проектах без токенов в репозитории.
- **Компактные ноды:** `get_nodes` / `get_node` по умолчанию отдают короткий вид (состояние, онлайн, трафик, inbound'ы по названиям, нагрузка сервера) — в разы меньше токенов; `full: true` — полный ответ панели.

- **Приватность:** имена компьютеров клиентов в списке устройств (`DESKTOP-…`) заменяются псевдонимами.
- 36 автотестов.

## 1.2.0 — 2026-09-30
- **Расширение Claude Desktop (`.mcpb`)**: установка двойным щелчком, без Node.js, git и правки JSON; API-токен хранится в защищённом хранилище системы. В каждом релизе — файл под каждую версию панели: `remnawave-3.0.mcpb` … `remnawave-3.4.mcpb`.
- **Проверка версии панели:** если версия панели отличается от версии сборки, в чате появляется предупреждение с подсказкой, какой файл скачать; версии видны в `panel_overview`.
- **Готовые отчёты:** `panel_overview` (пользователи, онлайн, ноды онлайн/офлайн, трафик, истекающие подписки), `user_report` (всё о клиенте за один вызов), `sharing_suspects` (вероятная раздача подписки по IP, приложениям и устройствам — только счётчики и псевдонимы).
- **Шаблоны запросов** в меню Claude: сводка по панели, разбор клиента, кто делится подпиской, проверка нод.
- **Бережём ноды:** повторный GeoCheck той же ноды в течение 30 минут и списки подключений в течение 2 минут отдают прошлый результат; размер списков ограничен 200 за запрос.
- **Меньше токенов:** компактный JSON без пустых полей и дублей (`rawInbound`), длинные списки сокращаются с пометкой «показано N из M» вместо обрыва ответа.
- **Безопасность:** тексты ошибок панели тоже проходят фильтр приватности.
- **Автотесты (33):** в т.ч. проверка, что ни одна команда не отдаёт ключи и данные клиентов; запускаются в CI, в проверке новых версий панели и перед релизом.
- CI: `npm audit`, сборка расширения; релизы по тегу `v*` с описанием из CHANGELOG.

## 1.1.1 — 2026-09-30
- Правила маршрутизации Xray (`"ip": ["geoip:private"]`) больше не превращаются в псевдонимы — заменяются только настоящие IP-адреса.
- Скрываются `shortIds` Reality.
- Сборка совместима с TypeScript 7 (явно подключены типы Node).
- Контракт Remnawave обновляется только под **стабильный** релиз панели: новый workflow `panel-release.yml` раз в сутки сверяет «Latest» релиз `remnawave/panel` и открывает PR. Dependabot больше не трогает контракт и zod, остальное проверяет ежедневно.
- В User-Agent клиентов идентификатор устройства (например, `Happ/…/Android/1789…`) заменяется псевдонимом `hwid~…`.

## 1.1.0 — 2026-09-30
- **Приватность.** Новый параметр `REMNAWAVE_PRIVACY` (по умолчанию `strict`):
  - всегда скрываются учётные данные: приватные ключи Reality, SECRET_KEY, пароли, VLESS UUID, ссылки подключения, shortUuid и URL подписки клиента;
  - в `strict` личные данные клиентов (username, email, Telegram ID, IP, HWID, описание) заменяются псевдонимами вида `user~3fa2c1` — одинаковые значения дают одинаковый псевдоним, псевдоним можно передать обратно в команду.
- Команды, которые только отдают ключи подключения и «сырую» подписку, скрыты (открываются в `REMNAWAVE_PRIVACY=off`).
- Дополнительные команды включаются, только если их поддерживает установленная версия контракта.
- Контракты без пометок чтение/запись: GET считается чтением.
- Dependabot: еженедельная проверка новых версий `@remnawave/backend-contract`.
